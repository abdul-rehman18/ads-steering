Architecture · Google Ads + Meta Ads · 10 EU countries + US · mock data

One queue, one owner per item, and nothing counts as done until the platform says so.

A steering system that keeps each country on its monthly budget, judged on Shopify revenue. It audits weekly, finds root causes, and acts through a single queue: proposal, approval, dry run, apply, read back, undo. Shown here on 60 days of mock data with three problems planted on purpose.

Sources

Shopify is the only source of truth for revenue. Meta and Google both claim some of the same orders, so their ROAS is shown but never added up and never used to steer.

TruthShopify ordersRevenue per country, and per campaign through the UTM on each order
SpendGoogle AdsCampaign spend, budgets, claimed conversions, search terms, change history
SpendMeta AdsAd set spend and budgets, ad level frequency, Purchase events with pixel and event id
FeedMerchant CenterProducts submitted and disapproved per country, with the reason

Schedule

Every day
06:00 CET
  1. Is every source fresh? If not, freeze raises
  2. Do platform claims still match Shopify? If not, freeze that country and open a task
  3. Did any campaign's Shopify revenue collapse? Run root cause, open a task
  4. Did anyone change a budget by hand against the rules?
  5. Pace each country against its month
  6. Apply only the small trims the rules allow
Every Monday
07:00 CET
  1. Search terms with spend and no sales
  2. Feed disapprovals
  3. Tracking problems
  4. Creative fatigue
  5. Pacing, then a short summary for Slack
When a person acts
Any time
  1. Approve or reject an item
  2. Apply it: dry run, write, read back
  3. Undo it, through the same path
  4. Mark a manual task done

The queue

Every change and every task lives in one queue, stored in SQLite with a change log and a full event history. Each item has an owner and a deadline. The same problem is queued once.

Rules it cannot break

Never pauseOnly lower a budget, never to zero, never below 5 EUR a day
Raise slowlyAt most +20% per step, at least 3 days apart per campaign or ad set, counting raises made by hand in the platforms
Never ramp across monthsNo raises in the last 3 days of a month, and every budget goes back to plan on the 1st
No raises on bad dataFrozen in a country with broken tracking, late data or an open root cause
Shopify decidesA campaign is only raised if it earns at least 2.5 EUR of Shopify revenue per EUR spent
Checked twiceThe hard rules, the freezes and the automatic limit are checked when proposed and again at the moment of writing

Where Claude sits

ClaudeJudges search termsCode picks terms with spend and no sales. Claude says which ones nobody buying a plush toy would type. Code refuses any negative that holds a product word or a word buyers also use, so "free plush toy sewing pattern" becomes "sewing pattern", and "fabrication" (made in France) is never used
ClaudeWrites the Monday summaryEvery number is a reference that code fills in. A digit typed by Claude rejects the summary and a plain template goes out
Code, not ClaudeEverything elsePacing, budgets, root cause tests and every write. Without an API key the system still runs on plain rules

Five ways it breaks in production

GuardTracking breaksSteer on Shopify only. Claims vs orders checked daily. Raises frozen
GuardWrite says OK but did not happenRead back against the dry run. Failed if different, and the owner is told
GuardHand edit in the meantimeLive value checked before writing. Marked stale, nothing written
GuardLate dataYesterday missing from any source freezes raises everywhere
GuardChanges pile upQueued once a day, rules and freezes rechecked at write, hand edits count, reset to plan each month

Each guard has a test. Not built in this slice: real API sign in, Slack approval buttons, the scheduler itself, currency conversion.
